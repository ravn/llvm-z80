## Tier C — Mechanism-blocked optimization candidates

These were not "deferred for time" — they hit a structural blocker.
Listed here so the blocker work itself is on the visible plan.

### `#178` — ADD_HL_rr / LD_HL_a16 rematerialization
- **Blocker:** pseudos have no SSA output (HL implicit physreg def);
  `isReMaterializable` silently ignored.
- **First drill (≤30 min):** prototype a wrapper pseudo with an
  explicit SSA def and measure whether `isReMaterializable` then
  fires.  If yes, the path forward is a TableGen / pseudo-expansion
  refactor; if no, the blocker is deeper in the remat machinery.
- **Yield estimate (untested):** ~5–20 B per BIOS-class function
  if remat fires.

### `#172` — A-pin accumulator — **PARKED 2026-05-30** (regalloc route empirically a wash)
- **Status:** five approaches, all net-negative/neutral (greedy hints,
  structural AReg pin, single-candidate, tied-AReg pseudos, connected-
  component carrier pin).  The 2026-05-30 connected-component rewrite
  (`z80-loop-carrier-areg-pin` @ `76125a9e7bc0`) is the first that is
  *correct* (parallel-accumulator + call gates → no segfault, no
  miscompile, AES 13/13 PASS) yet still a **wash**: default `-Oz`
  +3 B / +532 ts (+0.005 %); prod_like +3 B / +100 ts (+0.001 %).
- **Root cause (settled):** A is the universal contended 8-bit resource
  (sole ALU dest; sole operand for IN/OUT/LD (nn),A).  AES hot paths keep
  several 8-bit values live at once; only one can be ALU-resident, the
  rest must shuttle through A.  Pinning the carrier *relocates* the
  shuttle (to whatever it displaces from A) and adds a materializing LD
  at the component boundary — **shuttle count is conserved.**  SDCC pays
  the same shuttles on the same register file, which is why production
  AES already beats it (−11 % faster / −23 % smaller).
- **Only actionable reopen path:** ISel snapshot-rotate reshape (emit the
  carrier as the XOR *destination* with a separate snapshot vreg) —
  multi-week work whose payoff is bounded by a target that already wins.
  Not worth it; flag stays default-OFF.  See #172 close-out comment
  (2026-05-30) and `Z80PinAluAccumulator.cpp` attempt-3 commit message.
