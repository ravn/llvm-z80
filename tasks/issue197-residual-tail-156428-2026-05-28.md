## The remaining 13 are ONE upstream root cause: llvm/llvm-project#156428
The residual errors are all "Using an undefined physical register" and split as:
- **9** — `LD (HL),B/D` spilling the live i16 loop counter (`test_167_iy_crc32`).
- **1** — `AND_A` in `AND A; SBC HL,BC` (SUB_HL_rr lowering, `test_98`).
- **1** — `SRL_H` (`test_12`), **1** — `LD (IX-31),B` (`test_11`),
  **1** — `PUSH_HL` (`test_48` dynamic alloca).

All are **runtime-correct** (diff-oracle 799/0/50 + 793/0/50 throughout): the
values are actually present; only the liveness *metadata* is wrong.

**Mechanism (= #156428):** `LiveVariables` (HandlePhysRegUse / FindLastPartialDef)
adds spurious super-register implicit-defs (e.g. `implicit-def $hl` on an
instruction that only writes `L`) because it assumes writing one half of a pair
clobbers the other.  On Z80 the halves are **independent**.  The existing
`Z80FixupImplicitDefs` pass (addPostRewrite) removes the spurious defs that are
super-registers of an *intended* sub-register def — which fixes the
MachineCopyPropagation miscompile symptom.  The 13 residual errors are the
**inverse symptom**: a spurious super-reg implicit-def makes a sub-register's
real def look clobbered, so a later legitimate use is reported as reading undef.

**Why my session helpers don't catch it:** `aIsDeadInto` / `isRegLiveAt`
(Z80RegisterInfo) read the corrupted liveness, so e.g. the SUB_HL_rr `AND A`
fix sees "A live" and declines to mark the don't-care read undef, even though
the verifier (recomputing) sees A undef.

## Why this is NOT a quick fix
- The 9 counter spills involve a **live** value (the counter high byte is used
  across iterations).  Marking its read `undef` would be a miscompile risk
  (tells later passes the value is don't-care).  The correct fix is repairing
  the liveness metadata, not undef-marking.
- The mitigation that *would* help (extending `Z80FixupImplicitDefs` to the
  undef-use direction, or fixing `LiveVariables` upstream) is the same class of
  miscompile-sensitive liveness work the existing pass already shows is
  delicate (it guards a real 275+19-instance miscompile).

## UPSTREAM FIX DESIGN (#156428) — pinned for next session

Root cause located: `LiveVariables::HandlePhysRegUse` (llvm/lib/CodeGen/
LiveVariables.cpp, ~line 252-257).  When a sub-register (e.g. L) is used and
there is no full def/use of the super-register (HL), it calls
`FindLastPartialDef(HL)` (returns the last def of ANY one sub-register) and adds
`implicit-def $hl` to that instruction -- WITHOUT checking that all of HL's
sub-registers are actually defined.  The code comment (line 251) even asserts
"All of the sub-registers must have been defined before the use of Reg!" but
never verifies it.  On Z80 (independent pair halves: writing L doesn't touch H),
defining only L then using HL wrongly claims HL is fully defined => the spurious
super-register implicit-def behind #156428.

Proposed fix (in HandlePhysRegUse, the FindLastPartialDef branch): only add the
implicit super-register def if every LEAF sub-register is actually defined:

    MachineInstr *LastPartialDef = FindLastPartialDef(Reg);
    if (LastPartialDef) {
      bool AllSubRegsDefined = true;
      for (MCPhysReg SubReg : TRI->subregs(Reg))
        if (TRI->subregs(SubReg).empty() && !PhysRegDef[SubReg]) { // leaf
          AllSubRegsDefined = false; break;
        }
      if (AllSubRegsDefined)
        LastPartialDef->addOperand(
            MachineOperand::CreateReg(Reg, /*IsDef=*/true, /*IsImp=*/true));
    }

Correct for x86 too (more precise: AX used after only AL defined no longer
claims AX fully defined).  Risk: LiveVariables is core (feeds regalloc), so even
though the fork builds only Z80/SM83, gate on full value oracle (default +
static-stack) + cpnos/BIOS byte check + lit + the residual-10 verifier count.
If it clears the residual 10 and stays clean, it both fixes the tail AND lets
`Z80FixupImplicitDefs` (the existing mitigation) eventually be removed.

Work it on branch `z80-156428-livevars` (created, empty).  Per
feedback_no_upstream_issues: fix lives in the ravn/llvm-z80 fork; a clean,
target-independent version is the candidate upstream patch (do not file
upstream directly).

## UPDATE 3 (2026-05-28, branch z80-156428-livevars): fix landed + SUBSUMPTION proven; residual root-cause corrected

Implemented the HandlePhysRegUse all-leaf-subregs-defined guard (above) in
`llvm/lib/CodeGen/LiveVariables.cpp`.  Built + gated.  Findings:

1. **The fix does NOT change the residual verifier count (still 10 default).**
   The residual 10 are NOT the HandlePhysRegUse spurious-super-reg-def issue.
   Reading the actual MIR (test_98 walk_three_buffers bb.2) shows the real
   mechanism: a **don't-care-A** read in the carry-clear `AND A` of the
   SUB_HL_rr/SADD_HL_rr lowering.  A is dead-defined by a preceding
   `CALL ... implicit-def dead $a`, then `AND A` reads it only to clear carry
   (A's value is irrelevant; only CF matters and CF is always 0 after AND A).
   In loops A cycles as pure garbage (defined by one carry-clear AND A, read by
   the next across the back-edge), so `aIsDeadInto` (Z80InstrInfo.cpp:703)
   correctly reports A *live* and declines to mark the read undef.  The verifier
   then flags the read as undef (no real reaching def).  Same shape for SRL_H
   (test_12) and the LD (HL),B/D counter spills (test_167/168/171/40).
   A safe fix needs an A-reaching-def dataflow (mark the read undef only when
   every reaching def of A is dead/undef): marking it undef unconditionally
   would miscompile a genuinely-live A carried across a 16-bit subtract, because
   `AND A` physically preserves A and the lowering relies on that.  Deferred to
   a focused session.

2. **PRODUCTION `+static-stack` is verifier-CLEAN (0 errors).**  All residuals
   are `-O2` dynamic-stack-only.  cpnos/BIOS/autoload build `+static-stack`, so
   the verifier CI lane can gate on the production config TODAY (green), with
   the dynamic-stack don't-care-A class tracked separately.

3. **SUBSUMPTION PROVEN.**  Added a hidden flag
   `-z80-disable-fixup-implicit-defs` (Z80TargetMachine.cpp) and ran the full
   differential oracle with the Z80FixupImplicitDefs mitigation OFF + the
   LiveVariables fix ON: **default 799/0/50/207, +static-stack 793/0/50/213,
   zero divergences in both** (= the documented baselines).  So the
   LiveVariables root-cause fix prevents the MCP miscompile (275 DE + 19 HL
   instances) the mitigation guarded — the mitigation's removal loop is now
   redundant.  Kept the mitigation ON by default because its
   `fullyRecomputeLiveIns` tail still clears 2 verifier errors (test_11,
   test_37; without it the count is 12 not 10).  A future focused session can
   delete the removal loop (keeping only the recompute) with this proof in hand.

**Net for this branch:** root-cause fix for #156428 landed + proven safe +
proven to subsume the workaround.  Does NOT reduce the verifier count (the
residual 10 are the separate don't-care-A class).  Verifier surface unchanged
at 10 default / 0 production; oracle baseline-identical in both configs.
