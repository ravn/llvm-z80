# #197 residual tail (13 O2 verifier errors) root-caused to upstream #156428 (2026-05-28)

## Where the verifier surface stands
This session took the `-O2 -verify-machineinstrs` surface from **360 → 13**
errors (~96%), all via Z80-backend-specific, oracle-gated, miscompile-free
fixes (SP-relative borrow #210, prologue PUSH_HL, CFG duplicate-successor,
expansion live-ins, AND_A/SBC_A_A don't-care reads, ADJCALLSTACKUP prune,
emitLargeOffsetAddr PUSH_AF).  Those are on `origin/main` (`cf2f512`, CI-green)
plus the branch `z80-197-verifier` (`fd5e378`).

## The remaining 13 are ONE upstream root cause: llvm/llvm-project#156428
The residual errors are all "Using an undefined physical register" and split as:
- **9** — `LD (HL),B/D` spilling the live i16 loop counter (`test_167_iy_crc32`).
- **1** — `AND_A` in `AND A; SBC HL,BC` (SUB_HL_rr lowering, `test_98`).
- **1** — `SRL_H` (`test_12`), **1** — `LD (IX-31),B` (`test_11`),
  **1** — `PUSH_HL` (`test_48` dynamic alloca).

All are **runtime-correct** (diff-oracle 799/0/50 + 793/0/50 throughout): the
values are actually present; only the liveness *metadata* is wrong.

**Mechanism (= #156428):** `LiveVariables` (HandlePhysRegUse / FindLastPartialDef)
adds spurious super-register implicit-defs (e.g. `implicit-def $hl` on an
instruction that only writes `L`) because it assumes writing one half of a pair
clobbers the other.  On Z80 the halves are **independent**.  The existing
`Z80FixupImplicitDefs` pass (addPostRewrite) removes the spurious defs that are
super-registers of an *intended* sub-register def — which fixes the
MachineCopyPropagation miscompile symptom.  The 13 residual errors are the
**inverse symptom**: a spurious super-reg implicit-def makes a sub-register's
real def look clobbered, so a later legitimate use is reported as reading undef.

**Why my session helpers don't catch it:** `aIsDeadInto` / `isRegLiveAt`
(Z80RegisterInfo) read the corrupted liveness, so e.g. the SUB_HL_rr `AND A`
fix sees "A live" and declines to mark the don't-care read undef, even though
the verifier (recomputing) sees A undef.

## Why this is NOT a quick fix
- The 9 counter spills involve a **live** value (the counter high byte is used
  across iterations).  Marking its read `undef` would be a miscompile risk
  (tells later passes the value is don't-care).  The correct fix is repairing
  the liveness metadata, not undef-marking.
- The mitigation that *would* help (extending `Z80FixupImplicitDefs` to the
  undef-use direction, or fixing `LiveVariables` upstream) is the same class of
  miscompile-sensitive liveness work the existing pass already shows is
  delicate (it guards a real 275+19-instance miscompile).

## Recommended next steps (focused session, not marathon-tail)
1. In the failing functions, find the spurious super-register `implicit-def`
   (likely `implicit-def $bc`/`$hl`/`$de` on a sub-register-only def) that the
   current `Z80FixupImplicitDefs` `getIntendedSubRegDefs` logic misses, and
   extend the pass to remove it — gated on full oracle + cpnos/BIOS byte check
   (it touches the same MCP-sensitive area).
2. Once the metadata is consistent, the don't-care singletons (`AND_A`,
   `PUSH_HL`) will be correctly markable by the existing conditional logic.
3. Long-term: the upstream `LiveVariables` independent-sub-register fix
   (#156428) is the real cure; coordinate per the staged-upstream plan.
