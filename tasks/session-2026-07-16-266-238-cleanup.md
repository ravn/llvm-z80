## Issues closed

### #266 — getInstSizeInBytes wrong for SM83 on SUB/ADC/SBC_HL_rr pseudos

SM83 lacks `ADC HL,rr` / `SBC HL,rr` (ED-prefix ops). ExpandPseudo emits
6-instruction byte-by-byte sequences instead. The size table returned the
Z80 values unconditionally:

| Pseudo         | Was | SM83 correct |
| -------------- | --- | ------------ |
| SUB_HL_rr_BO   | 6 B | 9 B          |
| ADC_HL_rr_CIO  | 7 B | 11 B         |
| SBC_HL_rr_BIO  | 7 B | 11 B         |

Root cause: `getInstSizeInBytes` has an early scoped block that queries
`STI.hasSM83()` (for MUL16/UDIV16/…). The three new cases were added
outside that block, where `IsSM83` is not in scope. The compiler caught
this; fix was to add the cases inside the existing switch.

Fix: `llvm/lib/Target/Z80/Z80InstrInfo.cpp` — cases added to the
`IsSM83`-aware switch block.

Lit test: `llvm/test/CodeGen/Z80/issue-266-sm83-pseudo-sizes.ll`
Checks SM83 byte-by-byte expansion (`ld a,l; sub; ld l,a; …`) vs
Z80 ED-prefix (`sbc hl,`). 38/38 PASS.

Commit: `1822bd0c14af`

### #238 — ADJCALLSTACKUP path selection sync invariant

`adjCallStackUpClobbersReg` (Z80RegisterInfo.cpp) and
`eliminateCallFramePseudoInstr` (Z80FrameLowering.cpp) both contained
duplicated threshold logic to pick between 4 expansion paths:

  - Erase (Amount == 0)
  - ADD SP,e (SM83 && Amount <= 127)
  - POP AF×N (Amount <= 16)
  - HL shuttle (Amount > 16)

A silent divergence here produces wrong liveness: RegisterInfo claims a
register is not clobbered, FrameLowering clobbers it anyway.

Fix: `AdjCallStackUpPath` enum + `classifyACSU(Amount, IsSM83)` inline
helper added to `Z80FrameLowering.h` (already included by both .cpp files).
Both sites now call `classifyACSU` and switch on the enum.

No behaviour change. 38/38 lit PASS.

Commit: `3d6ea7cb8d20`

## Also this session (ravn/z88dk, ravn/rc700-gensmedet)

**z88dk #270 / llvm-z80 #270 — va_arg wrong for clang-z80 under _DEVELOPMENT stdarg.h**

Root cause: `_DEVELOPMENT/common/stdarg.h` `__CLANG` branch used
`{ marker = (va_list)&last + sizeof(last); }`. clang-z80 copies named args
to local alloca slots (e.g. IX-2), not to the original stack position, so
`&last` points to the copy rather than the original stack arg. `IX-2+2 = IX+0`
(saved-IX) — garbage.

The classic `include/stdarg.h` was already fixed (`bb914a1857` in ravn/z88dk).
The `_DEVELOPMENT` path (generated from `_DEVELOPMENT/proto/stdarg.h` via m4)
was missed.

Fix: added `__LLVMZ80` guard before `__CLANG` in both proto and common headers,
deferring to `__builtin_va_start/arg/copy/end`. Committed `00d5f1b0` to ravn/z88dk.

## Lesson learned

**Never kill ninja mid-run.** Interrupting ninja (SIGTERM/SIGKILL or
`stop_bash`) corrupts the build-system state: the next invocation triggers a
full cmake re-scan, which touches timestamps on generated files and cascades
into a full rebuild of unrelated libraries (LLVMScalarOpts, LLVMipo, …).
Even with sccache this takes 10+ minutes. Always let ninja finish.
